# Elekta QA & Automation Toolkit — Knowledge Base v0.2

**Статус:** технический прототип и аудит исходного Excel, **НЕ ВАЛИДИРОВАН ДЛЯ КЛИНИЧЕСКОГО ПРИМЕНЕНИЯ**.

## Что создано

- `data/test_definitions.json`: **161** кодов QA из загруженной книги, исходные параметры, критерии и источники (не утверждены).
- `data/sop_versions.json`: **161** черновая SOP-карточка. Из них **130** содержат исходные секции шагов/анализа, **8** не имеют отдельного блока анализа, **23** не имеют отдельной/групповой SOP в книге.
- `data/equipment_profiles.json`: два логических профиля Versa HD. HexaPOD/Catalyst присутствуют только у A. iView/XVI/ABC **не подтверждены** по конкретным машинам.
- `data/program_preview.json`: детерминированное предложение программы QA для двух машин; **ни одна позиция не утверждена**.
- `data/fullpackage_fields.json`: **35** диагностических полей Agility.
- `data/source_registry.json`: **21** ключевой источник из матрицы. Их наличие/названия сверялись выборочно; индивидуальная проверка порога каждого теста не завершена.
- `data/source_spotchecks.json`: документарные примеры подтверждения темы/раздела, **не** подтверждения всех допусков.
- `data/sop_gap_tasks.json`: 23 задачи по дополнению SOP.
- `schemas/`: JSON Schema и проект нормализованной модели PostgreSQL.
- `src/qa_program_builder.py`: **безопасный офлайн** rule-based генератор, без клинических подключений.
- `tests/`: минимальные автоматизированные проверки.

## Проверка

Требуется Python 3.11. Для текущего офлайн-прототипа внешние Python-пакеты не нужны.
Результаты первоначальной сверки: [локальная проверка пакета](docs/INITIAL_REVIEW.md).

```bash
python -m unittest discover -s tests -v
python src/qa_program_builder.py outputs/program_preview.json
```

Генератор строит предварительную программу по профилю оборудования и режимам. Достаточно JSON с профилем или списком профилей. Выгрузка в Markdown показывает состав программы и причины по каждому тесту. [Правила и примеры запуска](docs/PROGRAM_BUILDER.md)

Первый проход проверки 31 приоритетного теста и черновики дополнений:

Обновление от 15.11.2026: [проверка заводских документов v0.4](docs/VENDOR_SOURCE_REVIEW_v0_4.md).
Найдены инструкции и уточнены 11 тестов, включая восемь открытых карточек v0.3.
Совместимость редакций с установками и локальные условия исполнения ещё не подтверждены.
Материалы `data/review_v0_4/` сохраняют новые версии отдельно от v0.3 и активного каталога.

Предыдущий этап: [дозиметрия и механика v0.5](docs/DOSIMETRY_MECHANICS_REVIEW_v0_5.md).
Проверены отдельные утверждения ещё для 33 тестов: **64 из 161** имеют частичную документарную проверку,
**97** ещё не рассмотрены. Сводный учёт без повторов — `data/review_v0_5/coverage.json`.
Выявленные расхождения и предложения не меняют активные критерии; полная валидация SOP и клиническое утверждение отсутствуют.

**Текущий итог v0.6:** [документарный проход по всем 161 тестам](docs/FINAL_DOCUMENTARY_AUDIT_v0_6.md).
Рассмотрены оставшиеся 97 строк: **161/161** имеют разбор отдельных утверждений, **0** строк остаются нерассмотренными.
[Построчные результаты](docs/REMAINING_SOURCE_REVIEW_v0_6.md) содержат подтверждения, расхождения и открытые вопросы.
Это завершение первого документарного прохода; **полностью валидированных SOP и клинических утверждений — 0**.
Сводный реестр и действия по каждому коду: `data/review_v0_6/review_index.json`.
Проверка SOP продолжается отдельным этапом и учитывает применимость редакций, эталонные значения и локальные критерии.

[Поправки к СОП v0.7](docs/SOP_AMENDMENTS_v0_7.md) охватывают 23 карточки. Реестр проверки по всем 161 тестам связывает версии карточек со страницами источников и локальными вопросами. Для просмотра отдельной записи используйте `python src/sop_review_register.py --test MEC-M3`.

См. `docs/WORK_HANDOFF.md`, `docs/SOP_POLICY.md`, `docs/TRACEABILITY_FINDINGS.md`.
Результаты из `program_preview.json` нельзя использовать как расписание клинического QA до подтверждения комплектации, выбора методик, baseline и утверждения специалистом.
