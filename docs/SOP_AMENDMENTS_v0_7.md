# Поправки к СОП по итогам аудита v0.7

Подготовлено 23 черновые поправки к карточкам. Каждая запись задаёт предлагаемый текст для конкретных полей и условия его проверки. Реестр входит в документарный этап. Полная валидация СОП и клиническое утверждение по всем карточкам ожидают дальнейшей проверки.

| Раздел | Карточки | Поправка |
|---|---|---|
| Механика | MEC-M3, MEC-D2, MEC-M6 | Приоритет более строгого предела для диафрагм, применимость пределов ODI, независимая ось для перекрестия. |
| Дозиметрия | DOS-A6, DOS-A10, DOS-A11 | Выбор источника для R50, условия измерения при 180°, разные расчёты для выхода и профиля. |
| ABC | ABC-M1, ABC-M3, ABC-Q1, ABC-D2, ABC-M4 | Отдельный учёт ежедневной проверки объёма и еженедельной проверки герметичности при применимости IFU. Уточнены проверка линейности и независимое измерение времени. |
| HexaPOD | HEX-D4, HEX-M1, HEX-M2, HEX-M3 | Область действия встроенных проверок и график независимого контроля шести осей. |
| SGRT и КТ | SGRT-D2, SGRT-M4, SGRT-M7, SGRT-A8 | Совмещение Catalyst+, раздельные показатели шлюзования и учёт Sentinel CT QA и 4DCT. |
| Визуализация | IMG-A3 | Связь приёмочных и периодических критериев с конкретными пресетами, фантомом и эталонными значениями. |
| VMAT и MLC | VMAT-A2, VMAT-M1, MLC-M2 | Область действия пределов для обычных и SRS-дуг, сравнение с открытым полем в DDC, обработка скорости лепестков и событий PRF. |

Тексты оформлены в [реестре поправок](../data/sop_review_v0_7/amendments.json). Для MEC-M3 и двух карточек ABC поправки уточняют расхождения из предыдущего аудита. Значения из разных источников оставлены кандидатами в тех случаях, где выбор зависит от локальной методики или от версии оборудования. Источники для механики, дозиметрии и дуг приведены в [MPPG 8.b](https://doi.org/10.1002/acm2.14160) и [MPPG 9.b](https://doi.org/10.1002/acm2.14624).

| Состояние | Тестов | Следующее действие |
|---|---:|---|

| Исходная карточка в очереди проверки | 108 | Пройти по действующей версии карточки и её результатам аудита. |

Реестр формируется из каталога и записей v0.3–v0.7. Можно вывести итог, открыть карточку со страницами источников или получить все записи. У карточки с поправкой указан идентификатор родительской версии. Для MLC-M2 это черновик v0.4. Для HEX-Q2 указано, что основание локальных допусков предстоит документировать.

```bash
python src/sop_review_register.py
python src/sop_review_register.py --test MEC-M3
python src/sop_review_register.py --all
```

## Проверка полной карточки

1. Подтвердить оборудование, версию ПО, клинические режимы и применимость документа для каждой установки. Для КТ указать собственную модель и дыхательный интерфейс.
2. Сверить частоту, триггеры после обслуживания и измеряемую величину. Привязать каждый предел к источнику, локальному решению или протоколу приёмки. Записать основание выбора, если применимы разные пределы.
3. Проверить оборудование, геометрию, разрешение, калибровку и происхождение эталонных значений. Для расчёта зафиксировать входные данные, формулу, единицы, округление и трактовку границы допуска.
4. Проверить расчёт по контрольным данным. Включить результат на границе, превышение, пропущенный вход и случай, где разные показатели дают разные выводы. Для MEC-M3 такой случай возникает, когда оба края укладываются в геометрический предел, а изменение фактора выхода превышает допустимое. Для MEC-M6 использовать малую траекторию, смещённую относительно независимой оси. Для ABC проверить отдельные измерения, крайние значения диапазона и недостающие повторы.
5. Сверить форму записи, реакцию на отклонение и критерий повторной проверки. Зафиксировать использованные данные, версию карточки, результат методической проверки и ответственного медицинского физика.

Для начала локальной сверки нужны версии Integrity/TCS, XVI и iViewGT на каждой установке, версии iGUIDE и Catalyst/c4D там, где они используются, распределение ABC/Response и сведения о КТ с Sentinel. По количественным карточкам нужны протоколы приёмки и эталонные измерения. Эти данные проверяются в локальном контуре.
