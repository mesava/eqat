# Программа ГК по профилю оборудования

Генератор составляет проект программы из каталога 161 тестов, сведений об оборудовании и клинических режимах. Для каждой позиции он показывает решение и его основание. Протоколы приёмки, эталонные измерения и утверждение методик относятся к выполнению и оценке проверок. Для генерации эти данные не требуются.

Существующие профили A/B хранятся в [equipment_profiles.json](../data/equipment_profiles.json). В них сохранены известные системы и энергии. Для опций с неизвестным состоянием генератор отмечает связанные позиции как требующие уточнения. Правила применимости находятся в [applicability_rules.json](../data/applicability_rules.json). Версия правил указывается в выгрузке.

| Профиль | Включено | Уточнить | Вне профиля |
|---|---:|---:|---:|
| Versa HD A | 90 | 69 | 2 |
| Versa HD B | 65 | 60 | 36 |

## Запуск

```bash
python src/qa_program_builder.py outputs/program_preview.md
python src/qa_program_builder.py outputs/program_preview.json
python src/qa_program_builder.py outputs/custom_program.md --profiles profiles.json
```

В Markdown представлен список по каждой установке с периодичностью включённых тестов и причинами для остальных. В JSON также есть значения условий, категории тестов, критерии из каталога и основания для внеплановой проверки. Для своей конфигурации можно передать один профиль или список.

```json
{
  "id": "example_linac",
  "display_name": "Ускоритель с iViewGT",
  "scope": "linac",
  "photon_energies": ["6FF"],
  "electron_energies_MeV": [],
  "features": {
    "linac": "present",
    "agility_mlc": "present",
    "iviewgt": "present",
    "xvi": "absent",
    "vmat": "unknown"
  }
}
```

В этом примере проверки iViewGT входят в программу, проверки XVI и электронных пучков исключены по оснащению, а решение по VMAT ожидает сведений о режиме. Используйте `present` для подтверждённой функции, `absent` для подтверждённого отсутствия, `unknown` или пропуск для неизвестной. Пустой список энергий указывает, что соответствующий тип пучка отсутствует. При пропуске списка и явного признака тип пучка считается неизвестным.

Установленный модуль и используемый клинический режим задаются разными признаками. Например, `xvi` обозначает наличие системы, а `xvi_3d`, `xvi_static_2d` и `xvi_fluoroscopy` описывают конкретные режимы. Для ABC автоматический интерфейс задаётся через `abc_automatic_interface`. КТ с Sentinel описывается отдельным профилем `scope: "ct"` с признаками `sentinel_ct` и `respiratory_4dct`.

Правила текущей версии рассчитаны на семейство Versa HD/Agility и связанные модули из каталога. Каждый результат хранит выбранную карточку и исходную периодичность. Текстовые детали по клиническим режимам, отдельные энергии и диапазоны внутри одного теста остаются частью методики и доступны в выгрузке.
